# STATIC ONE-PAGE FIT

> 状态：待 PMO 验收

## 结论

**Static-only fit：条件成立（Conditional YES），不是无条件 YES。** 只有当页面内容被严格限制为稳定品牌、服务概览、信任、地域与直接联系，并由客户持续拥有套餐/PDF/法律/档期更新责任时，纯 HTML/CSS/少量 JS 才适配。

## 硬门槛逐项判断

| 门槛 | 结论 | 证据与边界 |
|---|---|---|
| 静态 HTML/CSS/少量 JS 可完成 | Conditional YES | 品牌、Victoria 简介、服务层级、证明、服务区、tel/mailto 可静态完成 |
| 单页在外链前独立完成决策 | YES（若内容经客户确认） | 可在页内说明是谁、适合谁、三类服务、为何可信、联系下一步 |
| Backend dependency | NONE for proposed page | 不建表单、数据库、CMS、预约、登录、支付；使用 `tel:`/`mailto:` |
| Content stability | MIXED | 品牌/经历/地域相对稳定；人数、套餐、费用、法律流程、场地细节和年份会变 |
| Ongoing content owner | CLIENT | 客户负责套餐 PDF、价格、人数、档期、法律信息、年份和社交内容 |
| External-system boundary | EXISTING CLIENT ASSETS ONLY | 可外链客户现有 PDF、Instagram/Facebook、地图；我方不登录、不配置、不维护 |
| 联系闭环 | YES | 电话和公开邮箱足以完成询盘；若客户必须保留服务器表单，则超出纯静态页能力或需外部既有系统 |

## 稳定内容（可进入静态页）

- Always Love 品牌与 Victoria Smith-Webb 个人定位。
- Mudgee 及周边服务区域（最终区域需客户确认统一版本）。
- 婚礼/私奔或微婚礼/大型聚会/葬礼与纪念服务的高层概览。
- 经客户核权的精选证明、资质表述与 Testimonials 摘要。
- “如何合作”的稳定流程：初聊 → 确认适配/档期 → 共同准备仪式。
- 电话、邮箱、社交/地图外链。

## 不应由我方承诺维护的内容

- 实时档期、价格、定金、证书/政府费用。
- 25/30 人等套餐阈值、套餐包含项、场地许可/保险状态。
- Marriage Act 或其他法律义务的更新与准确性担保。
- 社交 feed、新闻、近期婚礼、活动。
- WordPress Contact form、反垃圾、人机验证、邮件投递。

## 已有系统与替代风险

现站是 WordPress，含服务器表单和近期更新的套餐 PDF。改成静态单页会：

- 获得更轻、更聚焦、移动首屏稳定的体验；
- 但失去客户现有 CMS/表单能力，除非将它们留在客户现有系统并外链；
- 可能破坏已有 SEO 索引、多个服务入口和现供应商工作流；
- 若只是修复 hero、统一人数和做缓存/图片优化，现站供应商可能以更低风险完成。

## 私有 Cold Demo 概念假设（未来另授权后）

Demo 只应证明一个可证伪命题：

> “在 390px 移动首屏内，固定展示 Victoria 是谁、服务谁/哪里、三类核心仪式和一个直接联系 CTA；随后在同一页用稳定摘要、真实信任与清晰下一步完成自我筛选，并把当前套餐/档期明确留给客户确认。”

4. 不复制现站 Logo、图片、评价或完整文案，使用占位/原创结构，客户素材需后续核权；
5. 不含表单、后台、预约、支付、CMS 或实时数据。
